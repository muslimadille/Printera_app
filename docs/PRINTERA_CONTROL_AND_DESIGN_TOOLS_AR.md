# Printera — جرد التحكم (CRUD) + خطة أدوات التصميم

> إجابة على: **إيه اللي أقدر أضيفه/أحذفه/أعدّله في الموقع وإيه اللي ثابت؟** ثم **إزاي
> نضيف التحكم الناقص**، و**إزاي نبني: رسم Die Cut، وضع صور المنتجات على الجواني مع
> Rotate، معاينة 3D للتصميم النهائي، وعرضه كبوستر إعلاني بخلفيات.**
> مبني على قراءة الكود فعليًا. للتنفيذ: راجع `docs/design-tools/SPEC-01-TEMPLATE-CRUD-DB.md`.

## ١. جرد التحكم — إيه ليه CRUD وإيه ثابت

### ✅ ليها تحكم كامل (ديناميكي، يعدّله المستخدم)
| العنصر | المكوّن | التخزين |
|--------|---------|---------|
| **نوع الورق** (جراميات/مقاسات/أسعار) | `PaperTypesManager.tsx` | `user_settings['paperTypes']` |
| **المقاسات + تسعير الألوان ١–٤ + تكسير + سلفان + حقول مخصّصة** | `PriceSettingsPanel.tsx` | `user_settings['priceSettings']` |
| **التشطيبات** (ورنيش/يوفي/فويل…) | `FinishingServices.tsx` | `user_settings['finishingItems']` |
| **هوامش الربح** | `ProfitMargins.tsx` | `user_settings['profitMargins']` |
| **المستخدمون/الموظفون/الصلاحيات** | `UserManagement` / `EmployeeManagement` | جداول `app_users` / `user_tab_permissions` |
| **العروض المحفوظة** | `SavedQuotes.tsx` | جدول `saved_quotes` |

### ❌ مالهاش تحكم (ثابتة في الكود — محتاجة مطوّر + deploy)
| العنصر | ليه ثابت | أين |
|--------|----------|-----|
| **القوالب / الـ Templates / الـ Die Cuts** | كل قالب **محرّك TypeScript مكتوب بإيد** | `src/lib/{key}/{types,reference,geometry,nesting}.ts` + `components/boxes/{Key}Calculator.tsx` + `tabRegistry.ts` |
| **مكتبة ألوان/أحبار مسمّاة (Spot/Pantone)** | غير موجودة ككيان؛ الموجود "عدد الألوان" + تسعيره فقط | `ColorCountSelect` / `PriceSettings` |
| **العملة (ر.س) + الضريبة (VAT)** | مثبّتة في الكود | `SavedQuotes`/التنسيق |
| **كتالوج التابات/الحاسبات** | ثابت | `tabRegistry.ts` / `AppTabs.tsx` |
| **خريطة أوجه الـ 3D لكل قالب (faceCoords)** | ثابتة في كل Calculator | `components/boxes/*` + `Box3DPreview` |

**الخلاصة:** الأسعار والورق والتشطيبات **مرنة**؛ أما **القوالب والهوية (العملة/الضريبة/الألوان المسمّاة)** فـ**جامدة**. أكبر فجوة = **القوالب**.

---

## ٢. إزاي نضيف التحكم الناقص

- **القوالب (الأهم):** انقل **الكتالوج والبيانات الوصفية** للداتابيز (جدول `templates`) مع
  بقاء **محرّكات الهندسة كود** في المرحلة الأولى (هجين). ده يدّي أدمن CRUD (إضافة/تسمية/
  تصنيف/تفعيل/ترتيب/تسعير/صلاحيات) **بدون deploy**. التفاصيل في `SPEC-01`. (لاحقًا:
  محرّك بارامتري data-driven لإنشاء قوالب جديدة بالكامل من الواجهة.)
- **مكتبة ألوان مسمّاة:** جدول `inks/colors` (اسم، كود Pantone/CMYK، تكلفة) + ربطها بالتسعير.
- **العملة/الضريبة:** إعداد على مستوى الحساب (نسبة ضريبة، عملة، "شامل/غير شامل") — بند الموجة ١ في خارطة الطريق.
- **كتالوج التابات:** يتبع نفس فكرة سجل القوالب DB-managed.

## ٣. خطة أدوات التصميم (Design Tools)

الحلو إن **الأساس موجود جزئيًا** — نبني عليه بدل الصفر:
> `DielineImportDialog.tsx` · `dielineImport.ts` · `dielineGeometry.ts` · `pdfToSvg.ts` ·
> `InteractiveSvgCanvas.tsx` · `Box3DPreview.tsx` (Three.js + faceCoords) · محرّكات الرصّ `autoNest*`.

### أ) رسم / إنشاء Die Cut
٣ مسارات (من الأعملي للأقوى):
1. **مولّد أشكال قياسية بارامتري** — تختار نوع علبة وتُدخل الأبعاد → dieline يتولّد. (ده الموجود لقوالبه المدمجة؛ نوسّعه + DB-managed.) **الأسرع.**
2. **استيراد + توسيم SVG/PDF (الأنسب للـ self-service):** ترفع dieline موسوم CUT/CREASE/HOLES، وwizard يربط L/W/H بالمناطق ويحفظه كقالب. **يبني على `DielineImport`.**
3. **محرّر رسم حر (CAD-lite):** لوحة بـ Konva/Fabric/paper.js لرسم القص/التبييض/الطي واشتقاق الطي 3D + الرصّ. **الأقوى والأصعب.**

**التوصية:** (١)+(٢). المجهود: (١) متوسط · (٢) كبير + مخاطرة · (٣) كبير جدًا.

### ب) صور المنتجات على الجواني + Rotate + 3D للتصميم النهائي
البنية (3D + SVG canvas) موجودة؛ الجديد:
1. **محرّر فن لكل بانل:** سحب الصورة على بانل + move/scale/**rotate**/crop (Konva/Fabric).
2. **تركيب:** رندر فن كل بانل على canvas مستقل.
3. **تكسية الـ 3D:** استخدام canvas البانل كـ **texture على الوجه المقابل** في Three.js (UV mapping عبر `faceCoords`) → **معاينة 3D للتصميم النهائي بالصور**، تلفّها وتشوفها. المجهود: متوسط–كبير.

### ج) عرض كبوستر إعلاني (خلفيات)
1. **مُركّب بوستر:** رندر الـ 3D (أو صورة المنتج) فوق **خلفية مصمّمة** + نص/شعار → تصدير PNG/PDF عالي الدقة (Konva/Fabric + `scene.background` وإضاءة/ظل في Three.js). متوسط.
2. **ترقية AI:** خلفيات lifestyle مولّدة بموديل صور + تركيب المنتج (البنية الـ AI موجودة للصوت). قيمة تسويقية "wow". متوسط–كبير.

## ٤. الترتيب المقترح (موجة "أدوات التصميم")

تُوضع **بعد الموجة ١** (الضريبة/العملاء/الداشبورد) في خارطة الطريق:

1. **القوالب DB-managed (Template CRUD)** — يشيل أكبر جمود، قيمة إدارية فورية، وأساس للباقي. → `SPEC-01`.
2. **استيراد Die Cut بارامتري** — self-service حقيقي، يبني على `DielineImport`.
3. **محرّر الفن على البانلات + 3D مُكسّى** — يستغل الـ 3D الموجود.
4. **مُركّب بوستر** (ثم خلفيات AI).

| البند | مجهود تقريبي | مخاطرة | يعتمد على |
|-------|:-----------:|:------:|-----------|
| القوالب DB-managed (Phase 1: كتالوج) | ٤–٧ أسبوع | منخفضة | — |
| محرّك بارامتري data-driven (Phase 2) | ١٠–١٦ أسبوع | عالية | Phase 1 |
| استيراد Die Cut بارامتري | ٨–١٢ أسبوع | متوسطة–عالية | DielineImport |
| محرّر الفن + 3D مُكسّى | ٦–١٠ أسبوع | متوسطة | Box3DPreview |
| مُركّب بوستر (+AI) | ٤–٨ أسبوع | متوسطة | محرّر الفن |

> **ابدأ بـ Template CRUD (Phase 1):** هجين آمن — الكتالوج في الداتابيز، والمحرّكات تفضل
> كود. تفاصيله الكاملة وخطوته العملية الأولى في `docs/design-tools/`.
